### Меры по обработке конфедициальных данных

1. Каждому пользователю присваивается своя роль в системе. Доступ к роли определяется на основе RBAC/ABAC. Соблюдается принцип минимальных привилегий.
   * Администратор может просматривать только записи на прием. При этом может видеть только ФИО пациента, ФОИ врача и время записи на прием. Доступа к мед.картам/анализам нет.
   * Бухгалтер имеет доступ только к данным оплаты услуг и договорам. Доступа к записям на прием и мед картам клиентов нет.
   * Доктор может просматривать данные пользователя, которые касаются приема (мед. карты, анализы, ФИО, история хронических заболеваний из анкеты). При этом у доктора отсутствует доступ к паспортным данным, телефону. Доктор также имеет доступ только к данным своих пациентов.
   * Пациент может просматривать/редактировать все свои данные в профиле. При этом у пациента нет доступа к каким-либо данным других пациентов.
   * Аналитики не имеют доступа к персональным данным пользователей. Вместо этого они работают с маскированными данными. Например, вместо Иванов И.И они видят Пациент№1.
2. Оригинальные персональные данные пользователей хранятся в специальном сервисе шифрования. Этот сервис в зависимости от тега и данных выдает специальный токен PD_ID, который другие сервисы хранят в своих базах. При необходимости получить персональные данные сервис ходит в сервис шифрования с этим токеном. Если от пользователя поступит запрос на удаление персональных данных из системы достаточно удалить записи в одном сервисе шифрования. В других сервисах останутся просто безымянные токены.
3. Сервисы между собой взаимодействуют по защищенному протоколу TLS 1.2+.
4. Передача данных внешним партнерам в лабораторию: передаются маскированные данные без привязки к конкретному человеку. Например, Пациент№1, дата рождения, список анализов, последние цифры паспортных данных ****34. Сами результаты анализов лежат в специальном объектном хранилище в зашифрованном виде (через AES-256).
5. Все действия пользователей логируются через специальный сервис, что позволяет проводить аудит всех действий пользователей в системе.
6. Необходимо разработать инструменты для архивирования данных пациентов:
   * Данные мед. карты необходимо хранить 5 лет с даты последнего посещения пациента. Если пациент продолжает обращаться — срок отсчитывается от последнего визита.
   * Срок хранения бухгалтерской документации - 5 лет
   * Журналы учёта, справки, направления, результаты анализов хранятся от 1 до 5 лет, в зависимости от типа документа.
   * Тип данных определяется на основе тегов
7. Внедрить Collibra Data Intelligence Cloud для автоматического сканирования хранилищ данных, проверки применения тегов и уведомлений, если данные остались без меток.
8. Разработать обучающие модуди для сотрудников по работе с конфедициальными данными.
